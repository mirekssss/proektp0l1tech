СПЕЦИФИКАЦИЯ ТРЕБОВАНИЙ К ПРОГРАММНОМУ ОБЕСПЕЧЕНИЮ
====================================================
Проект: Клиент-серверное приложение с алгоритмами
Группа: 251-353 (специальность «Информационная безопасность»)
Версия: 1.0
Дата:   2026-06-13
====================================================


1. ВВЕДЕНИЕ
-----------

1.1 Назначение
    Настоящий документ описывает требования к клиент-серверному приложению,
    реализующему набор алгоритмов (шифр Виженера, SHA-512, метод деления
    пополам, поиск кратчайшего пути в графе) с поддержкой многопользовательской
    работы, базы данных и ролевого разграничения доступа.

1.2 Область применения
    Система предназначена для учебной демонстрации принципов защиты информации,
    сетевого программирования и проектирования клиент-серверных архитектур.

1.3 Определения
    Сервер      — приложение main_server, принимающее TCP-соединения.
    Клиент      — приложение frontend_client с графическим интерфейсом (Qt Widgets).
    Роль        — атрибут пользователя: «user» или «admin».
    Сессия      — состояние авторизованного подключения клиента на сервере.
    Синглтон    — объект, существующий в единственном экземпляре в процессе.


2. ОБЩЕЕ ОПИСАНИЕ
-----------------

2.1 Контекст системы
    Клиент подключается к серверу по TCP (порт 33333). После авторизации
    клиент отправляет команды; сервер выполняет их и возвращает результат.
    Несколько клиентов могут быть подключены одновременно.

2.2 Основные функции системы
    — Регистрация и авторизация пользователей.
    — Выполнение алгоритмов по запросу клиента.
    — Хранение пользователей в SQLite-базе данных.
    — Разграничение доступа по ролям (admin / user).
    — Управление пользователями со стороны администратора.
    — Отображение истории операций в графическом интерфейсе.

2.3 Характеристики пользователей
    Пользователь (user)  — авторизованный клиент, имеет доступ ко всем
                           алгоритмам; не может управлять учётными записями.
    Администратор (admin)— расширенный доступ: просмотр и удаление
                           учётных записей пользователей.

2.4 Ограничения
    — Язык реализации: C++17.
    — Фреймворк: Qt 6 (Core, Network, Sql, Widgets, Test).
    — СУБД: SQLite (встроенная, без отдельного сервера БД).
    — Сборочная система: CMake 3.16+, Ninja.
    — Поддерживаемые ОС: Windows 10/11 (основная), Linux (Docker).


3. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
-----------------------------

3.1 Сервер

    ФТ-С-01  Сервер должен принимать TCP-соединения на порту 33333.
    ФТ-С-02  Сервер должен поддерживать одновременную работу не менее 10 клиентов.
    ФТ-С-03  При подключении клиента сервер отправляет приветственное сообщение.
    ФТ-С-04  Сервер разбирает входящую строку по формату «action&payload\n».
    ФТ-С-05  Каждая команда обрабатывается независимо; ошибка одного клиента
             не влияет на остальных.
    ФТ-С-06  При отключении клиента его сессия удаляется из памяти сервера.
    ФТ-С-07  Сервер логирует события в стандартный вывод (qDebug).

3.2 База данных

    ФТ-БД-01 БД реализована как синглтон (DatabaseManager::instance()).
    ФТ-БД-02 При первом запуске автоматически создаётся таблица users
             (id, login UNIQUE, password_hash, role).
    ФТ-БД-03 Если таблица пуста, создаётся учётная запись admin/admin.
    ФТ-БД-04 Пароли хранятся в виде SHA-512 хэша.
    ФТ-БД-05 Логин администратора «admin» не может быть удалён.

3.3 Регистрация и авторизация

    ФТ-РА-01 Команда reg&login,password — регистрирует нового пользователя.
             Возвращает «OK: Registered» или «ERROR: …».
    ФТ-РА-02 Повторная регистрация с занятым логином возвращает ошибку.
    ФТ-РА-03 Команда auth&login,password — проверяет учётные данные.
             При успехе возвращает «OK:user» или «OK:admin».
    ФТ-РА-04 При неверном логине/пароле возвращается «ERROR: Invalid credentials».
    ФТ-РА-05 Команда logout — сбрасывает сессию текущего соединения.

3.4 Алгоритмы

    ФТ-АЛ-01 Шифр Виженера (vigenere_enc / vigenere_dec):
             — Шифрует/расшифровывает только латинские буквы.
             — Регистр символов сохраняется.
             — Нелатинские символы передаются без изменений.
             — Ключ должен содержать хотя бы одну латинскую букву.

    ФТ-АЛ-02 SHA-512 (sha512):
             — Вычисляет хэш произвольной строки.
             — Возвращает 128-символьную hex-строку (нижний регистр).

    ФТ-АЛ-03 Метод деления пополам / sqrt (bisect):
             — Вычисляет квадратный корень методом бисекции (60 итераций).
             — Принимает неотрицательное вещественное число.
             — Точность не хуже 1e-10.

    ФТ-АЛ-04 Кратчайший путь в графе BFS (graph):
             — Фиксированный граф из 7 вершин (рёбра: 1-2,1-3,2-4,2-5,
               3-5,3-6,4-7,5-7,6-7).
             — Возвращает длину кратчайшего пути или сообщение «No path».
             — При невалидной вершине возвращает ошибку.

3.5 Роли и администрирование

    ФТ-РО-01 Администратор имеет доступ к командам admin_users и admin_delete.
    ФТ-РО-02 Пользователь с ролью «user» при вызове admin-команд получает
             «ERROR: Access denied».
    ФТ-РО-03 admin_users — возвращает список всех пользователей (login:role),
             разделённых «|».
    ФТ-РО-04 admin_delete&login — удаляет пользователя; нельзя удалить «admin».

3.6 Клиент

    ФТ-КЛ-01 TcpClient реализован как синглтон (TcpClient::instance()).
    ФТ-КЛ-02 Клиент подключается к localhost:33333; параметры задаются
             в константах TcpClient.
    ФТ-КЛ-03 Все запросы выполняются синхронно с таймаутом 2 секунды.
    ФТ-КЛ-04 Результат каждой операции отображается в соответствующей метке.
    ФТ-КЛ-05 Каждая операция добавляет строку в таблицу истории запросов.
    ФТ-КЛ-06 Таблица истории поддерживает сортировку по любому столбцу.
    ФТ-КЛ-07 Таблица истории поддерживает фильтрацию по содержимому столбца.
    ФТ-КЛ-08 Панель администратора отображается только при входе с ролью admin.


4. НЕФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
--------------------------------

4.1 Производительность
    НФТ-П-01 Время ответа сервера на одну команду — не более 500 мс.
    НФТ-П-02 Сервер выдерживает не менее 10 одновременных подключений
             без деградации производительности.

4.2 Безопасность
    НФТ-Б-01 Пароли не хранятся в открытом виде — только SHA-512 хэш.
    НФТ-Б-02 Роль пользователя проверяется на стороне сервера при каждом
             запросе к admin-командам.
    НФТ-Б-03 Учётная запись «admin» не может быть удалена никем.

4.3 Надёжность
    НФТ-Н-01 Некорректный формат команды не вызывает сбой сервера;
             возвращается сообщение «ERROR: …».
    НФТ-Н-02 Внезапный разрыв соединения не нарушает работу других клиентов.

4.4 Переносимость
    НФТ-ПЕ-01 Серверная часть собирается и запускается в Docker-контейнере
              на базе Ubuntu 22.04.
    НФТ-ПЕ-02 Код использует только стандарт C++17 и Qt 6 без платформенно-
              зависимых вызовов.


5. СИСТЕМНЫЕ ИНТЕРФЕЙСЫ
------------------------

5.1 Протокол TCP
    — Порт: 33333.
    — Кодировка: UTF-8.
    — Разделитель команд: символ новой строки '\n'.
    — Разделитель ответов: '\r\n'.

5.2 Формат команд (клиент → сервер)
    ┌──────────────────┬───────────────────────────────────────────────┐
    │ Команда          │ Описание                                      │
    ├──────────────────┼───────────────────────────────────────────────┤
    │ reg&login,pass   │ Регистрация                                   │
    │ auth&login,pass  │ Авторизация                                   │
    │ logout           │ Выход из сессии                               │
    │ stats            │ Статистика (количество пользователей)         │
    │ admin_users      │ Список пользователей (только admin)           │
    │ admin_delete&log │ Удаление пользователя (только admin)          │
    │ vigenere_enc&t,k │ Шифрование Виженера: текст t, ключ k          │
    │ vigenere_dec&t,k │ Расшифровка Виженера                          │
    │ sha512&text      │ SHA-512 хэш строки text                       │
    │ bisect&value     │ Квадратный корень методом бисекции            │
    │ graph&s,t        │ Кратчайший путь от вершины s до вершины t     │
    └──────────────────┴───────────────────────────────────────────────┘

5.3 Формат ответов (сервер → клиент)
    Успех:  «OK:…» или результат вычисления.
    Ошибка: «ERROR: описание».
